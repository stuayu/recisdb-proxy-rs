# Codex への委譲

このリポジトリでは実装作業を Codex CLI へ委譲できる。指揮役(このセッション)は
**調査・仕様の確定・差分レビュー**を担当し、コードを書く作業は Codex に渡す。

## 前提の確認

```bash
which codex && codex --version
```

モデルとリーズニング強度は `~/.codex/config.toml` の既定値ではなく、
**呼び出しごとに `-c` で明示する**(既定は `model_reasoning_effort = "low"` なので、
実装作業には弱すぎる)。

## 呼び出し方

仕様書をファイルに書いてから渡す。プロンプトを直接コマンドラインに埋めない
(長い日本語がシェルのクォートで壊れる)。

```bash
S="$SCRATCHPAD"          # セッションのスクラッチパッドディレクトリ
cat > "$S/task.md" <<'PROMPT'
（仕様書。書き方は下記）
PROMPT

codex exec \
  --sandbox workspace-write \
  -c model=gpt-5.6-luna \
  -c model_reasoning_effort=medium \
  --skip-git-repo-check \
  "$(cat "$S/task.md")" 2>&1 | tail -120
```

- 長時間かかるので `run_in_background: true` で投げ、出力ファイルを後から読む。
- 続きを頼むときは `codex exec resume --last "追加の指示"` で同じセッションを継続する
  (新規 `codex exec` はコンテキストを捨てて最初からやり直す)。
- `--sandbox workspace-write` はワークスペース内の書き込みのみ許可する。
  ネットワークが要る作業(依存追加で `cargo fetch` が走る等)は事前に
  こちら側で `cargo add` 等を済ませておくか、承認付きで実行する。

## 並列実行

独立したタスクは同時に投げてよい。ただし **同じファイルを触らせない**。
仕様書の「制約」節に、他の作業者が触っているファイルを名指しで
「触らない」と書くこと。特に衝突しやすいのは:

- `web-ui/src/styles.css`(全画面で共有。複数タスクが追記すると上書きし合う)
- `recisdb-proxy/src/web/api/mod.rs`(ルート登録)
- `Cargo.toml` / `package.json`

これらに触るタスクは直列に流す。

## 仕様書の書き方

Codex は**コールドスタート**で、この会話の文脈を一切持たない。次を必ず含める。

1. **背景** — なぜこの変更が要るのか。現状の実装がどうなっているか(ファイルパス付き)
2. **やること** — 節に分けて、変更対象のファイルパスを明示する
3. **不変条件** — `CLAUDE.md` の「絶対に守る不変条件」から、
   このタスクに関係するものを**抜き出して転記する**。参照だけでは読まれないことがある
4. **制約** — 触らせないファイル、入れさせないライブラリ、やらせないリファクタ
5. **検証コマンド** — `cargo build -p recisdb-proxy` / `cargo test -p recisdb-proxy` /
   `cd web-ui && npm run build` など、実際に流せるものを書く
6. **報告してほしいこと** — 「変更したファイルと、どう実装したかを簡潔に報告」

避けるべき書き方:

- API のフィールド名やテーブルの列名を**推測で書かない**。
  分からないときは「作業前に `<path>` を読んで実際の名前を確認すること。推測で書かない」と指示する
- 「いい感じに」「適切に」といった曖昧な指示。判断基準を数値か具体例で与える
- 大きすぎる一括依頼。1タスク = 1つのまとまった関心事に割る

## 委譲後のレビュー(省略しない)

Codex の報告を鵜呑みにしない。指揮役が必ず自分で差分を見る。

```bash
git diff --stat
git diff -- <触ったはずのファイル>
```

特に `CLAUDE.md` の不変条件に触れる差分は行単位で確認する。

- DB マイグレーション … 台帳への**追記**か(既存番号の書き換えでないか)、冪等か
- SQL の列とプレースホルダの数が一致しているか(過去に事故あり)
- チャンネル列挙順に影響していないか(影響するなら .ch2/ChSet 再生成の告知が要る)
- FFI 境界に panic し得るコードが入っていないか
- Web UI … 狭幅(360〜430px)で横スクロールしないか
- UI を変えたなら `npm run build` 済みか(`static/vue/` に反映されているか)

検証コマンドを Codex が「通した」と報告していても、指揮役が自分でもう一度流す。
